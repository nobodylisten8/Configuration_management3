# Проверка выполнения и оформления

## Этапы

| Ветка | Реализация | Проверка при завершении этапа |
| --- | --- | --- |
| stage1 | Язык и промежуточное представление | 5 тестов; четыре набора полей из задания |
| stage2 | Машинный код и двоичный файл | 12 тестов; все четыре эталона по 6 байт |
| stage3 | Интерпретатор, общая память, XML | 23 теста; копирование [5, -7, 0, 42] |
| stage4 | Исполнение ABS | 27 тестов; результат [13, 0, 21] |
| stage5 | Три вектора длины 8 | 33 теста; проверка входных массивов и XML |

Каждая ветка фиксирует завершение этапа. Все пять коммитов входят в main.
Во всех этапах выполнены Ruff и проверка оформления без нарушений.

## Перечень нарушений

| Правила | Проверка |
| --- | --- |
| С1–С5 | README.md, .gitignore, src, tests и run.bat включены в Git |
| С6 | Заголовки feat(stageN), содержательные тела с реализацией и проверками |
| Г1–Г5 | Архивы, бинарные файлы, окружения, кэши, IDE и сборки исключены |
| Р1 | Все файлы не длиннее 1000 строк |
| Р2, Р6 | Python не длиннее 80 символов, остальные файлы не длиннее 120 |
| Ф1 | Функции не длиннее 40 строк, включая docstring и пустые строки |
| А1 | Не больше 7 аргументов, включая self |
| К1 | Модули, классы, функции и методы имеют docstring |
| Ц1 | Сложность не выше 10; учтены вложенные условия и циклы |
| М1 | Числовых литералов непосредственно в сравнениях нет |
| И1 | Имена проверены Ruff по правилам PEP8 |

Правила для других языков неприменимы: реализация выполнена на Python.
При окончательной проверке максимальная длина функции — 20 строк,
максимальная сложность — 8. Независимая проверка Radon также дала 8.
Числовые данные примеров и двоичные коды ISA заданы явно; сравнения
границ в реализации используют именованные константы.

## Воспроизведение

```console
python -m pip install -r requirements-dev.txt
python -m ruff check .
python -m unittest discover -s tests -v
python -m tools.check_quality
python -m tools.demo
python -m compileall -q src tests tools
git diff --check
```

check_quality проверяет файлы, включённые в индекс Git. Перед проверкой
новых файлов нужно добавить их через `git add`. Кэши compileall остаются
локальными и исключены из Git. Все бинарные результаты в output/ также
исключены; текстовые XML в examples/expected служат эталонами тестов.

Для vector_mixed ожидается `[8, 3, 1, 0, 5, 13, 21, 34]`;
для vector_negative — `[1, 2, 3, 4, 5, 6, 7, 8]`;
для vector_boundaries — `[0, 67108863, 67108864, 1, 1, 0, 32767, 32768]`.
Во всех трёх дампах адреса 1100..1107 включительно, исходные данные
в 1000..1007 после исполнения не изменены.
