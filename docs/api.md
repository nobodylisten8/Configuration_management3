# Справочник функций и настроек

Основные функции и настройки также описаны в README.md.

## src/__init__.py

Ассемблер и интерпретатор учебной виртуальной машины, вариант 1.


## src/__main__.py

Запуск CLI через python -m src.


## src/assembler.py

Трансляция исходника через IR в двоичный машинный код.

* `assemble` — Записать бинарный результат и вывести размер и тестовые байты.

## src/cli.py

Аргументы командной строки и сообщения об ошибках.

* `build_parser` — Создать CLI с подкомандами assemble и run.
* `main` — Выполнить команду и вернуть ненулевой код при ошибке.

## src/codec.py

Кодирование и декодирование шестибайтовых инструкций little-endian.

* `encode_instruction` — Упаковать поля инструкции, обнуляя все неиспользуемые биты.
* `decode_instruction` — Прочитать поля; отклонить неверный размер, opcode и резервные биты.
* `encode_program` — Склеить инструкции без заголовка и разделителей.
* `format_bytes` — Форматировать байты аналогично примерам из спецификации.

## src/interpreter.py

Запуск двоичной программы и сохранение диапазона общей памяти в XML.

* `validate_range` — Проверить включительные границы диапазона дампа.
* `dump_memory` — Записать XML с адресами и значениями ячеек, включая обе границы.
* `interpret` — Загрузить, выполнить программу и сохранить дамп после успеха.

## src/isa.py

Описание полей шестибайтовых инструкций варианта 1.

* `Operation` — Мнемоника, код операции и ширины полей после A.
* `Instruction` — Проверенная инструкция в промежуточном представлении.
* `Instruction.fields` — Вернуть A, B, C, D в порядке полей спецификации.
* `validate_operands` — Проверить количество аргументов и диапазоны всех полей.
* `operand_bounds` — Вернуть диапазон поля; константа LOAD имеет знаковый формат.

## src/machine.py

Регистровая УВМ с общей адресуемой памятью команд и данных.

* `Machine` — Общая память целочисленных ячеек, 128 регистров и счётчик команд.
* `Machine.__init__` — Загрузить байты кода в начало обнулённой общей памяти.
* `Machine.check_address` — Не допустить выхода за границы, включая отрицательные индексы.
* `Machine.read_memory` — Прочитать одну ячейку общей памяти.
* `Machine.write_memory` — Записать одну ячейку, в том числе в область команд.
* `Machine.fetch` — Декодировать следующую команду непосредственно из общей памяти.
* `Machine.execute` — Выбрать обработчик инструкции без цепочки условных операторов.
* `Machine.run` — Выполнять команды по 6 байт до конца исходной области кода.
* `Machine.load_constant` — LOAD B, C: записать константу C в регистр B.
* `Machine.read_register` — READ B, C: прочитать M[R[B]] в R[C].
* `Machine.store_register` — STORE B, C, D: записать R[B] в M[R[D] + C].
* `Machine.absolute` — ABS B, C: записать abs(R[B]) в M[R[C]], сохранив регистры.

## src/parser.py

Разбор языка: мнемоника и числовые аргументы через запятую.

* `parse_integer` — Разобрать десятичное число или число с префиксом 0x/0b/0o.
* `parse_line` — Разобрать команду, игнорируя пустые строки и комментарий после ;.
* `parse_program` — Разобрать программу и добавить номер строки к сообщению об ошибке.

## tools/__init__.py

Проверки качества и воспроизводимые демонстрации.


## tools/check_quality.py

Строгая проверка ограничений оформления из задания.

* `git_output` — Получить текст Git без вывода секретов или параметров окружения.
* `tracked_paths` — Проверять только файлы, включённые в индекс Git.
* `function_complexity` — Учесть все ветвления, циклы, генераторы и логические операторы.
* `argument_count` — Посчитать также self, позиционные и именованные аргументы.
* `check_function` — Считать длину от def до последней строки, включая документацию.
* `is_number` — Распознать числовой литерал, в том числе с унарным знаком.
* `check_node` — Проверить функции, docstring и отсутствие чисел в сравнениях.
* `check_text` — Проверить размеры текстового файла и дерево Python.
* `check_file` — Проверить тип файла и добавить имя к сообщениям анализа текста.
* `check_commits` — Проверить Conventional/Scoped Commits и наличие подробного тела.
* `main` — Проверить индекс Git и завершиться с ошибкой при нарушении.

## tools/demo.py

Сборка и исполнение всех примеров с проверкой XML и исходных данных.

* `load_cases` — Прочитать независимые входные данные и эталоны примеров.
* `verify_xml` — Проверить корень, диапазон, адреса и значения XML-дампа.
* `run_case` — Собрать, выполнить и проверить один пример, вернуть путь к дампу.
* `main` — Создать локальные результаты; двоичные файлы не включаются в Git.

## Настройки и ограничения

* Python 3.10+; runtime-зависимостей нет.
* Формат файлов: UTF-8, при чтении исходника допускается BOM.
* Размер инструкции: 6 байт, little-endian, резервные биты нулевые.
* Регистры: 128; память по умолчанию: 65536 целочисленных ячеек.
* LOAD C: -67108864..67108863; STORE C: 0..32767.
* Диапазон дампа: --start и --end включительно, оба обязательны.
* --test ассемблера: байтовый вывод (в stage1 — поля IR).
* Аргумент memory_size конструктора Machine меняет размер памяти для тестов.
* Ограничения проверки заданы именованными MAX_* в tools/check_quality.py.
* Настройки стиля, именования, docstring и сложности: pyproject.toml.
* Инструменты разработки и их версии: requirements-dev.txt.
* Сборка примеров: python -m tools.demo; результаты: output/.
* Файлы эталонов и входных данных: examples/cases.json, examples/expected/.
